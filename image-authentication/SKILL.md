# Image Authentication

Define the authentication proposition and criteria: whether the scene is accurately represented, whether a specified alteration occurred, or whether a questioned source produced the image. Keep separate any content-identification question such as who or what is depicted. Limit task-irrelevant case information that could bias the examination. Assess whether the available image quality, quantity, and reference material permit a useful opinion; request additional images when needed and state when the examination must be limited or cannot be completed. Preserve source bytes, hash a working copy, and document processing contemporaneously. See [evidence integrity](../multimedia-authentication/references/evidence-integrity.md).

Form authentication and non-authentication propositions and testable alternatives. Examine **both** image structure (format, metadata, packaging, processing and sensor signals) and scene content (artifacts, physical consistency, photographic conditions, and relevant depicted features). Select tests that discriminate between explanations, compare suspicious regions with controls, and seek a series of related images or earlier originals when available. [Image methods](../multimedia-authentication/references/image-authentication.md) and the [manipulation workflow](../multimedia-authentication/workflows/image-manipulation-examination.md) give detailed decision points.

Do not interpret error-level analysis, metadata, or one detector as proof. Report observed features, how structure and content bear on each proposition, alternatives, limitations, and the strength of the opinion without unsupported numerical probability. Submit a final forensic opinion for independent review by a comparably trained examiner; an agent cannot serve as its own independent reviewer. Until review occurs, label the opinion preliminary and disclose that limitation. Follow [reporting guidance](../multimedia-authentication/references/reporting-and-limitations.md).

## Suggested SWGDE-based examination sequence

The source is [SWGDE *Best Practices for Image Authentication*, 18-I-001-2.0 (3 March 2025), §§ 6-9](https://www.swgde.org/wp-content/uploads/2025/03/2025-03-03-Best-Practices-for-Image-Authentication-18-I-001-2.0.pdf). It requires a question-specific process that considers both image structure and scene content. It is not a fixed menu of filters.

1. **Assess suitability.** Record the disputed feature, authentication criteria, rival propositions, and available image series or reference material. Establish whether resolution, focus, light, compression, or processing permit the proposed tests. Seek an earlier-generation image, original RAW/JPEG, or related frames if available; record why the examination must be limited if they are absent.
2. **Inspect structure and C2PA.** Identify bytes and file generation. Record format, header/footer or embedded objects, EXIF/XMP, thumbnail, color profile, dimensions, orientation, compression tables, and processing history. On the preserved image bytes, check for C2PA credentials and verify any available manifest as described below. Test a tag or structural mismatch against benign export behavior before assigning significance. Compare a source-camera claim with suitable exemplars rather than metadata alone.
3. **Inspect scene content.** At native scale and controlled magnification, inspect geometry, perspective, scale, lighting/shadows/reflections, depth of field, lens distortion, chromatic aberration, physical interactions, and continuity within a series. Record the exact source coordinates of each observation. Separate a staged scene from an edited file.
4. **Target signal tests.** Depending on the proposition, examine JPEG block/quantization changes, double compression, resampling periodicity, copy-move correspondence, CFA/demosaicing, local noise/PRNU, or edge/alpha behavior. Compare suspicious regions with matched controls and neighboring frames/images. Document preprocessing, thresholds, and how texture, saturation, recompression, and editing could mimic the result.
5. **Challenge the interpretation.** Try benign processing simulations or camera/export exemplars when warranted. Seek corroboration from a different signal or source version. Negative results from low-quality or recompressed images rarely exclude a subtle edit.
6. **Conclude and review.** Evaluate structure and content together; record supporting and contrary observations, test limits, and the opinion's strength. Avoid an unsupported numerical probability. The finding remains preliminary until independently reviewed by a comparably trained examiner.

## C2PA check for images

1. **Check availability.** Run a current [c2patool](https://github.com/contentauth/c2patool/blob/main/docs/usage.md) against the preserved working copy, for example `c2patool image.jpg` and `c2patool image.jpg --info`. Record the exact file hash, verifier version, command, full output and errors. Distinguish an embedded manifest, a supplied sidecar, a remote manifest, no manifest found, and a file or verifier error. Use the included [meta3.py](tools/meta3.py) with `python image-authentication/tools/meta3.py image.jpg` for a supplementary ExifTool metadata view when useful. It only calls `exiftool -json`; its output cannot establish that C2PA is present or absent, nor validate a credential. Do not use its `--remove` or `--extract-binary` options in an examination: the first creates a metadata-stripped derivative and the second is an unimplemented placeholder.
2. **Verify before interpreting.** If a manifest is available, record the active manifest and any earlier manifests; content binding, claim and signature validation; signer identity and certificate trust; timestamp and revocation status when available; actions, `digitalSourceType`, ingredients, and broken or missing links. Configure a current trust list using [c2patool's trust guidance](https://github.com/contentauth/c2patool/blob/main/docs/usage.md#configuring-trust-support); record its identity and retrieval date or hash, and label trust *not assessed* if no trust list was used. Check sidecar or remote retrieval separately where relevant. A valid signature plus content binding associates a signed claim with the tested bytes; it does not prove that each historical assertion or depicted event is true. If validation fails, report the specific failure and do not treat the manifest's origin claims as verified. See [content provenance](../content-provenance/SKILL.md) for lineage analysis.
3. **Assess synthetic-origin clues.** Inspect the active manifest **and ingredient history** for a declared `trainedAlgorithmicMedia`, `algorithmicMedia`, or `compositeWithTrainedAlgorithmicMedia` source type; generation or generative-edit actions; and named generators or services such as OpenAI. Quote the exact field, value and manifest or ingredient that contains it. A valid, content-bound credential explicitly declaring AI generation supports that narrower origin claim; a name in a signer, software, editor, or ingredient field alone does not show that the entire final image was generated. Separate whole-image generation from an AI-assisted edit or a generated ingredient. Test conflicts with camera/processing history and scene evidence rather than treating a provider name as a verdict.
4. **Report the limit.** State whether the credential was found, whether it validated, what generation clues it actually declares, and the resulting weight for the stated proposition. No C2PA manifest is non-diagnostic: credentials can be absent, stripped, or separated from the image. A failed or untrusted credential is a provenance concern, not itself proof of synthesis.

## Suggested open source tools and algorithms

| Purpose | Tool or algorithm | Consideration |
| --- | --- | --- |
| Metadata and packaging | [ExifTool](https://exiftool.org/) `-G1 -a -s -u`; `file`/libmagic; hex viewer | Metadata is editable; use format specifications and a second parser for a contested field. |
| C2PA provenance | [c2patool](https://github.com/contentauth/c2patool) for verification; bundled [meta3.py](tools/meta3.py) for supplementary ExifTool JSON | Record content binding, signature, trust and source claims separately. `meta3.py` is a metadata reader, not a C2PA verifier. |
| Raw pixel inspection | [OpenCV](https://docs.opencv.org/), [Pillow](https://pillow.readthedocs.io/), [scikit-image](https://scikit-image.org/docs/stable/) | Preserve original orientation and color interpretation; record every crop/transform. |
| JPEG history | `jpegio`/JPEG coefficient parser, quantization-table and block-grid comparison | Uneven compression or ELA is only a lead; modern exports and texture create false patterns. |
| Copy-move and resampling | Feature matching (e.g. ORB/SIFT where licensed), block matching, periodicity analysis | Repeated architecture or texture can mimic copies; report geometric transform and false matches. |
| Sensor/source comparison | Validated PRNU correlation with same-device exemplars and controls | Requires sufficient image quality and controlled exemplars; processing can erase or distort signal. |

For a manipulation-specific path use the [image workflow](../multimedia-authentication/workflows/image-manipulation-examination.md). Do not treat a visual heatmap or AI classification as a standalone forensic conclusion.
